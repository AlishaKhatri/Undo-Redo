A stack is the right choice for an undo and redo system because a stack follows the Last In, First Out principle. 
This means the most recent action is the first action that can be removed. 
In an editor, this makes sense because when a user presses Undo, they usually want to reverse the last change they made. My program uses one stack for completed actions and another stack for actions that have been undone. If the user chooses Redo, the most recently undone action is moved back to the undo stack.
A queue is better for a help desk because a queue follows the First In, First Out principle. Customers should normally be helped in the order they entered the system. For example, if Jordan enters the queue before Taylor and Morgan, Jordan should be helped first. Using front and rear pointers helps keep customers in the correct order.
My implementations are different from Python's built-in lists because I created the Stack and Queue classes manually using Node objects. Each Node stores a value and a pointer to the next Node. The Stack keeps track of the top Node, while the Queue keeps track of both the front and rear Nodes. Python lists already provide built-in methods for adding and removing items. Building these structures manually helped me understand how stacks and queues work internally and why their ordering rules are useful in different programs.
